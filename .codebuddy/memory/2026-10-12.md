# 2026-10-12（二）：中证全指数据补全 + 全库覆盖审计

## 根因：TDX 官方 hsjday 包系统性停更一批指数
- `sh/lday/sh000985.day`（中证全指）在 20260817/20260901/20260910 三个包里都只到 **2016-06-13** ——
  不是导入丢数据，是源头文件就停了。数据库忠实映出缺口。
- **系统性**：SSE 000xxx 段共 **144 个中证系列指数停更**（000801~000999 大量与 000985 同日停在
  2016-06-13；另一批停在 2018-12-25 / 2019-01-30 / 2021-02-04）；SZSE 399xxx 段 **109 个**停更；
  另有 ~2222 个停更的是退市股/失效 888xxx 等（正常现象）。
- 审计方法（可直接复用）：解析 zip 内全部 .day 的首末记录（只读首末 32 字节即可）vs
  `dbbaroverview` 的 start/end 对比。结论：**导入环节 0 缺口**（zip 末日期 vs 库末日期全部一致，
  容差 7 天），唯一不一致是 sz200b07（见下）。

## 修复：runIndexSupplement.py（新工具，东方财富补指数日线）
- 数据源：`https://push2his.eastmoney.com/api/qt/stock/kline/get?secid=…&klt=101&fqt=0`
  （免鉴权；secid：SSE=`1.代码`，SZSE/BSE=`0.代码`；fields2 顺序=日期,开,收,高,低,量,额）。
- **已验证与 TDX 数据在衔接日 2016-06-13 逐字段一致**（开高低收完全相同、量差<1e-4、额=元）。
- 注意：**东财 000985 历史只从 2011-08-02 起**；2005~2011 段靠库里原有 TDX 数据，重叠区由
  `VNPYdataWriter.write_tdx_day` 增量逻辑自动跳过（只追加库末日期之后的 bar，幂等可重跑）。
- 用法：`python runIndexSupplement.py --symbols 000985.SSE[,000906.SSE]`，然后
  `python runTDXchuquan.py --symbol 000985`（指数恒等复制，秒级）。
- **结果**：000985.SSE 现在 2005-01-04 ~ 2026-10-12 共 5285 条，dbbardata/fwd/bwd 三表逐行一致；
  `price_IndexBeiLi` 默认 10 年区间 + 默认基准中证全指直接可用（2411 交易日/2406 有效点）。
- pytdx 在线（get_index_bars）取不到 000985（0 条）；腾讯接口只有近 640 根 —— 东财是唯一可用全历史源。

# 2026-10-12（三）：批量补全全部停更指数 + 在线通道 bug 修复

## runIndexSupplement.py 重写（直写 sqlite，批量 --auto）
- **性能**：vnpy `save_bar_data`（insert_many.on_conflict_replace）写 2500 条要 60s+；
  改直写 sqlite `executemany INSERT OR REPLACE` → **1885 条 0.69s**。不经 vnpy，启动也快。
- 新增能力：`--auto`（按 dbbaroverview 找出库内停更>120 天的指数段标的 SSE 000xxx / SZSE 399xxx /
  BSE 899xxx 并全部补）；`--dry-run`；**衔接校验**（东财在库末日期收盘价 vs 库内，偏差>0.5% 跳过，
  防代码对应错证券）；**量纲换算**（东财量/库量≈10 整次幂时按 1/ratio 换到 TDX 单位，如 000832 中证转债差 100×）。
- 写库只追加「库内最大日期之后」的 bar，同事务维护 dbbaroverview 的 count/start/end，幂等可重跑。
- 注意：东财对**已失效/退市代码**返回空 JSON 或直接 `Remote end closed connection`（限流也这样）——
  批跑时会漏掉个别真实可补的（本次 26 个失败里 6 个是限流误伤，二次重试补回）。重跑 --auto 幂等。

## 批量补数结果（2026-10-12）
- 共补 **65 个 SSE 指数**（含 000985 上次会话）：58 批跑 + 4 重试 + 000171/000821/000806。
  停更指数段从 244 → **179**（剩余 70 SSE + 109 SZSE 均东财无数据 = 已退市/失效的细分指数，无法补）。
- 全市场复权同步：`runTDXchuquan.py` 全量跑 **19m41s**（12399 标的，增量 67 + 全量重建 4，
  新增 fwd+bwd 共 26.8 万行）。批量补数/复权都要 **Start-Process 后台 + 轮询**（会超 execute_command 超时）。
- 三表一致性抽查（000985/000806/000902/000988/000832/000171/000821/000824）：dbbardata==fwd==bwd 逐行一致。

## 在线通道 read_tdx_day_online 4 个 bug（已修，TDXdataRead.py）
1. **指数用错 API**：原 `get_security_bars` 对指数恒返 0 条 → 应 `get_index_bars`（新增
   `is_index_symbol_tdx`：sh000/88/999、sz399、bj899 判指数）。
2. **年份限制阻断回补**：原 `if start_dt.year <= now.year-1: return []` 使停更超一年的标的永不能在线补数 → 删除。
3. **连接失败崩溃**：原 `with api.connect(...)` 在连接失败时 connect 返回 False → 报
   `'bool' object does not support the context manager protocol` → 改显式 `if not api.connect(...): continue` + `finally: api.disconnect()`。
4. **翻页漏数据**：原 `max_per_request=(end-start).days+1` 可能 >800（pytdx 上限）→ 封顶 800 翻页。
